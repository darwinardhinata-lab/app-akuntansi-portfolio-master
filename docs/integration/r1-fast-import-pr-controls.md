# R1 purchase-return CLI and HTTP controls

`import:pr` requires the existing A2 console context: one active MGI company verified by `OperationalCompany`, legacy sync and customs disabled. The company is not taken from the file. HTTP retains its request authorization and uses the same `PurchaseReturnEligibility` service to lock the owned PO and check completed-return quantities by an unambiguous PO item before commit. The CLI also requires an exact SKU match to the PO line and its product and requires the CSV price to match the PO; inventory uses carrying cost.

Use a CSV with one consistent PO and ISO date per return number, positive integer quantities, unique SKU rows per return, and plain decimal prices with up to two decimal places. Identical normalized documents are recognized by a fingerprint stored in the existing import notes on the completed return. A changed document or older return without a matching fingerprint is rejected, not rewritten. The file is written in one transaction; journal identity remains `source_doc_no = return_number`.
